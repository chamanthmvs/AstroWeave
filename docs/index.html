One question. Multiple perspectives.

03 / the manager

Coordination above complexity.

The Astrologer Manager is the top-level intelligence. It coordinates the system without absorbing the detailed reasoning logic of every specialist.

01

Understand

02

Delegate

03

Evaluate

05 / v2 implementation

v2 works end to end. The system is still in progress.

AstroWeave can accept a question and birth details, create a chart-backed specialist analysis, and synthesize an answer. It is an active prototype, not a production service.

AVAILABLE NOW

End-to-end flow

Authenticated users can start or resume conversations in the browser. The orchestrator selects career, finance, love, or sports specialists, reuses one birth chart per run, combines their conclusions, and saves the completed turn.

CONFIGURABLE

Models and charts

LLM providers are selected through environment configuration. Chart calculation runs as a separate HTTP service, keeping the orchestration backend independent.

NEXT UP

Grounded reasoning

Knowledge retrieval, astrology-source citations, and real Vedic/KP-specific analysis are planned. Today, methodology selection is passed to prompts but does not yet change retrieval or chart logic.

Backend and orchestration

FastAPI exposes health, authenticated run, conversation-list, transcript, and deletion endpoints. A run builds request context, invokes the compiled orchestrator graph, and returns the answer, state, and execution trace. Failures from chart or provider calls are surfaced as a clear gateway error — or a 503 when the chart service is unreachable — instead of a raw server error.

The v2 orchestrator loads bounded session and prior-conversation history, classifies the request, executes each specialist task, collects every result, synthesizes the response, and persists the completed turn. Conditional routing repeats task execution until the queue is empty.

Specialists and state

The shared specialist graph runs planner, executor, collector, evaluator, and synthesizer stages for each requested domain. The executor sends the query, methodology, and chart data to the configured LLM and records structured analysis, conclusion, and confidence results.

The current registry includes career, finance, love, and sports. Shared state carries bounded history, specialist selection, methodology, chart data, results, errors, persistence status, and execution progress.

Frontend and accounts

The single-page web app provides registration, sign-in, conversation creation, resumption and deletion, transcript display, a question form, methodology selection, and a light/dark theme toggle. Birth details are collected at registration, securely geocoded for India with verified TLS, stored with the account, then submitted with each request.

Accounts use a local SQLite store with scrypt password hashing. Sign-in issues an expiring bearer token that the FastAPI backend verifies on each request; this remains a development authentication flow, not a production identity system. Date-of-birth uncertainty is captured in the UI, but backend chart handling for an unknown date is not implemented yet.

LLM and context controls

Provider selection supports OpenAI-compatible providers, OpenAI, and Anthropic through environment variables. Provider and model values can be overridden globally, by role, or by specialist. API keys are intentionally kept outside the repository.

Optional context-size protection is available through ASTROWEAVE_CONTEXT_CHAR_LIMIT. When enabled, over-limit hand-offs degrade gracefully instead of allowing a request to fail without a clear state error.

Chart calculation service

Birth-chart calculation is isolated behind a separate FastAPI service. It provides planet positions, ascendant, divisional charts, dasha-bhukti, bhava charts, and ashtakavarga over HTTP; the main backend configures its URL with ASTROWEAVE_CHART_SERVICE_URL.

The service uses PyJHora, an AGPL-3.0 dependency. It remains a standalone service with its own environment and no shared application code, so the orchestration backend stays independently deployable.

Tests and observability

Seventy-four automated tests cover authentication, durable history, owner isolation, idempotent request fencing, routing, specialist execution, dispatcher behavior, chart-client failure handling, state reduction, and API contracts. The suite runs without provider keys or chart-service access.

Application logging records request activity and LLM reasoning fields. Each run also returns an execution trace of the specialists consulted, which the web app surfaces beneath every answer.

Under active development; not production-ready

07 / the v2 task loop

Every planned specialist gets a turn.

After each specialist subgraph finishes, AstroWeave records the result and returns to task selection while work remains. Once the queue is empty, the collected perspectives move to response synthesis.

“The synthesizer should not concatenate outputs. It should make the result coherent while preserving meaningful methodological differences.”
